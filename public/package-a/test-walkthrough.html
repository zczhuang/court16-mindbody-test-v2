Testing Package A end-to-end

A 20-minute hands-on tour of every behavior Cedarwind built. Reproducible from a laptop with the production HubSpot portal open in another tab. No real customer harm — all test artifacts get cleaned up at the end.

For
Ibtissam + Anthony — verify Package A behaves the way the SOW described before flipping any workflow live.
Where
Production stack — booking app at court16-mindbody-test.vercel.app, HubSpot portal 4832170.
Cost
Zero real bookings. The MindBody sandbox flag (MINDBODY_USE_SANDBOX_FALLBACK=true) is still on, so all writes hit MindBody's -99 sandbox, not Court 16's live MindBody. HubSpot gets real test Deals + Contacts — those get archived at the end.

Pre-flight check (30 seconds)

Open these tabs in your browser, signed in to each:

  • HubSpot — Deals view (portal 4832170)
  • Booking app — court16-mindbody-test.vercel.app
  • Tracker — /tracker.html (for crossref)

You'll be jumping between the booking-app tab + the HubSpot Deals tab a lot. The HubSpot Deals view should show all 13 of Court 16's pipelines.

Test 1 · Kids trial submission creates a Deal Anyone

The simplest behavior to verify: a parent submits the trial form, a Deal lands in HubSpot.

1.1

Submit a fake trial

  1. Open the booking-app homepage
  2. Click Kids free trial
  3. Pick any location (let's say Newton)
  4. Pick any class from the calendar
  5. Fill the form. Use test+kids-walkthrough@cedarwind.io as the email so it's easy to spot in HubSpot later. Make the child 6 years old.
  6. Submit. You should land on the "we'll be in touch" confirmation screen.
ExpectThe confirmation page shows a correlation ID (a short hex string). Copy it — you'll need it for later steps.
1.2

Find the Deal in HubSpot

  1. Switch to your HubSpot tab → Sales → Deals
  2. Change the pipeline dropdown to KIDS TRIALS (NEWTON)
  3. You should see a brand-new Deal named something like "Kids trial — <child name> · NY - Newton" at the top, in the Requested Trial column
  4. Click the Deal to open it
Expect The Deal has:
  • A Court 16 correlation ID property matching the one from step 1.1
  • A Court 16 Booking property group on the Contact (scroll the related-contact card)
  • The contact has all 13 court16_* properties populated
GotchaIf you don't see the Deal in Newton's pipeline but it landed in another pipeline (or no pipeline), check that the booking-app form used the right location. The pipeline-to-location mapping lives in config/hubspot-deals.ts.

Test 3 · Staff confirm moves the Deal forward Stuart

Verifies that when staff clicks the "Confirm" link in the (future) staff notification email, the Deal advances from Requested Trial to Scheduled Trial.

3.1

Build the signed staff URL

The staff URLs are HMAC-signed by Cedarwind's app. They live as Contact properties on each booking. From your test booking in Test 1:

  1. HubSpot → click the parent Contact (from the Deal's right-rail "Contact" association)
  2. Scroll the Contact's properties → Court 16 staff confirm URL — copy the value
ExpectA URL like https://court16-mindbody-test.vercel.app/api/staff/confirm?token=<signed-jwt>
3.2

Click it

Open the URL in a new tab. (In production this link is in the staff notification email.)

Expect
  • A simple "Confirmed" HTML page
  • HubSpot Deal: stage flips to Scheduled Trial
  • HubSpot Contact: Court 16 booking status flips to confirmed
  • MindBody sandbox: the child is now booked into the class (sandbox-only)
GotchaIf you click the URL twice, the second click returns "This booking is already confirmed" (HTTP 410). That's the single-use guarantee enforced via the Contact's status field — not via a separate token table. Working as designed.

Test 4 · Deny action Stuart

Verifies the new Spec 5 functionality: deny with a 5-reason picklist.

4.1

Get the deny URL

Submit a fresh kids trial (repeat Test 1 with a new email like test+deny@cedarwind.io). On its Contact, copy the Court 16 staff deny URL property.

4.2

Open the deny URL

Paste it into a browser. You'll see a form with 5 radio buttons (Wrong age band / No availability / Parent cancelled / Duplicate booking / Other) and an optional note field.

4.3

Submit a denial

  1. Pick a reason (e.g. "Wrong age band")
  2. Click Deny + send email
Expect
  • HTML page confirming the denial
  • HubSpot Deal: Denial reason property = "Wrong age band", Denial note empty (unless you picked "Other")
  • HubSpot Contact: Court 16 booking status = failed, Court 16 failure reason = "Denied: Wrong age band"
NoteMindBody booking-cancellation is documented as a TODO — the deny route flips the Deal + Contact state but doesn't yet auto-remove the client from the MindBody class. Track 2 enhancement; for now staff cancels in MindBody admin if needed.

Cleanup Anyone

To leave Court 16's HubSpot clean after the walkthrough:

  1. HubSpot → Deals → filter by Deal name contains "test" or "walkthrough" — bulk-archive each test deal
  2. Contacts → filter by email contains "@cedarwind.io" with "walkthrough" in the local-part — bulk-archive each test contact

HubSpot keeps archived records for 30 days, so accidental archives are recoverable from Recently deleted.

TipCedarwind also has a 2-factor cleanup script (filter by court16_correlation_id HAS_PROPERTY + name pattern) that only catches Cedarwind-tagged test artifacts and never touches real-customer Deals. Ask Stuart if you'd like that run instead.

If something fails

Every booking-app POST returns a JSON trace with one entry per integration step. To see it: when submitting via the UI, open DevTools → Network, find the book/trial or book/intro request, click Response. The trace array shows each step's status (ok / error / skipped) with the actual HubSpot or MindBody error message attached.

Most common failure modes:

  • HubSpot 400 INVALID_OPTION on preferred_location — means our location-to-dropdown map drifted (rare, fixed in 2026-05-12)
  • MindBody usertoken/issue 500 — sandbox is flaky; the booking still completes via the graceful-degradation path (Contact gets court16_booking_status=manual_review)
  • HubSpot form-submit 400 FORM_HAS_RECAPTCHA_ENABLED — the reCAPTCHA toggle in spec 9 still needs flipping. Deal creation still works (different API path).
