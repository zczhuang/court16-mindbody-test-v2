Email copy + workflow assembly

Everything you need to finish Package A: 4 email bodies (copy-paste ready) + 4 workflow walkthroughs. Total time ~45 minutes. After this, the booking app sends parents the right email at every state transition automatically.

TL;DR

  1. Open 4 emails in HubSpot — Marketing → Email → find each by name (search "[Cedarwind]"). For each, paste the Subject + Preheader + Body from below.
  2. Publish each email (right-side "Review and publish" → "Publish").
  3. Open 4 workflows in HubSpot — Automation → Workflows → search "[Cedarwind]". For each, drag in 1–2 actions per the instructions, save.
  4. Turn on each workflow when you're ready for real customers (top-right toggle).

Part 1 · Email copy (paste into HubSpot)

For each email below, navigate in HubSpot:

  • Marketing → Email (top nav)
  • Search the listed name in the search bar
  • Click the email → Edit
  • Settings tab → paste Subject + Preheader
  • Edit tab → click the body text module → paste the body HTML below — via the </> Source Code view (read the callout immediately below before pasting any HTML)
  • Review and publish top-right → Publish
📋 IMPORTANT — How to paste HTML into HubSpot's email body

HubSpot's rich-text editor renders pasted HTML as literal escaped text by default — you'll see <p>Hi {{ contact.firstname }}</p> as actual text on screen instead of "Hi Ibtissam,". The fix is one button.

  1. Click into the body text module → the rich-text toolbar appears at the top of the module
  2. On the toolbar, find the </> icon (usually right side of the toolbar, labeled Source Code on hover) → click it
  3. The view switches to raw HTML — paste the body code here
  4. Click </> again to flip back to WYSIWYG view → merge tokens like {{ contact.firstname }} render as friendly previews
  5. If anything looks broken (tags showing as text, missing line breaks), flip back to Source view and double-check the paste landed cleanly

How the variants workCedarwind's /api/staff/deny route writes the picklist label + optional note into the Contact's court16_failure_reason property (e.g. "Denied: Wrong age band"). The HUBL {% if "..." in contact.court16_failure_reason %} blocks above match on that text. If you change the picklist labels in the deny form, also update the matched strings here.
HUBL preview gotchaHubSpot's email editor's "Preview" tab doesn't always render HUBL conditionals against a sample contact — you may see all 5 variants stacked. That's a preview-only quirk; the real send only renders the matching block. To verify, go to the workflow's Test tab and enroll a real test contact with each failure reason value.

Known gaps (Track 2 follow-ups)

  • Class date/time merge tokens: emails reference "class time" generically since the booking app doesn't yet store a class_date Deal property. Cedarwind extends this in a Track 2 commit.
  • Per-location password-setup link: Email 2's CTA points at court16.com/login (generic). Optional polish via Smart Content keyed on court16_location_slug.
  • MindBody booking auto-cancellation on deny: /api/staff/deny flips state correctly but doesn't yet remove the client from the MindBody class (needs visit-id we don't capture from AddClientToClass — Track 2).
  • Reason picklist drift: if you change Cedarwind's deny picklist labels, the HUBL conditionals in Email 4 need a matching update.
