📋 IMPORTANT — How to paste personalization tokens & HTML in HubSpot

When you copy {{ contact.firstname }} into a HubSpot field, HubSpot shows it as literal text — not a live merge token. There are three different fields that need three different fixes. Use the right one for the right field.

FIELD USE WHY
Subject line Path A — Personalize button Plain text only, no HTML
Preview text Path A — Personalize button Plain text only, no HTML
Body Path B (cleanest) — drag in an HTML module
…or Path C — Source Code </> on existing text module		 Has formatting + merge tokens
Path A · Subject + Preview text — use the Personalize button
  1. Open the email → in the right-side Edit inbox content panel, click the Personalize button next to the Subject line field (don't type a {{ }} token directly).
  2. A dropdown opens — pick the field (e.g. contact.child_name) → it inserts as a styled token chip you can place anywhere in the line.
  3. Repeat for the Preview text field.
  4. Don't type the token text by hand — it'll save as literal text.
Path B · Body — drag an HTML module from the left palette (recommended)

This is the cleanest path. HubSpot's HTML module accepts raw markup + merge tokens in one place — no need to fight the rich-text editor.

  1. In the editor, the left sidebar shows a + icon at the top — click it to open the Add panel (it's the default view, usually already open).
  2. Under Recently used modules (or scroll to All default modules → Base), find the module labeled HTML with a </> icon on the card.
  3. Drag the HTML module card into the email body — release it where you want the body copy to land (replacing or alongside any existing text module).
  4. Double-click the newly-dropped HTML module → a dialog opens with an HTML edit area.
  5. Paste the body HTML from this doc (e.g. the Email 1 body block below) → click Save.
  6. The preview updates: {{ contact.firstname }} renders as a token chip; bold/links work; lists render.

Tip: If you want to delete an existing text module first (e.g. the placeholder "Hello [First Name (Parent)]"), hover it → click the trash icon that appears in the module's hover toolbar. Then drop the HTML module in its place.

Path C · Fallback — flip an existing text module to Source Code view

Use this if you'd rather edit the existing text module (the one already in the template) instead of dragging in a new HTML module.

  1. Click into the body text module — the rich-text toolbar appears across the top of the module.
  2. Find the </> icon on the toolbar (usually the rightmost icon — hover to confirm the tooltip reads Source Code).
  3. Click it → the view flips to a raw HTML edit pane.
  4. Paste the body HTML from this doc → click Save on the dialog (or click </> again to flip back to WYSIWYG).
  5. Tokens render as token chips; if anything looks broken (tags showing as literal text), flip back to Source view and check the paste.

If you tried this on May 14 and it didn't work: The most common reason is clicking the section frame (blue overlay around the whole row) instead of the text module inside the section. Click the actual paragraph text — not the surrounding frame — to expose the toolbar. If you don't see the </> button at all, drag in a fresh HTML module via Path B instead — that's the more reliable route.

If you get stuck: bring up the email on the Friday call (1 PM ET) — we'll walk through it together. Path B (drag HTML module) is the cleanest if Path C still doesn't yield the </> button for you.
