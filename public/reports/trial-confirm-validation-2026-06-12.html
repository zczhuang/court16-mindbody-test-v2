Why one trial confirm failed on June 12

Companion log for the “Trial Process Review” thread. Two test trial requests were approved by staff on the morning of June 12, 2026 (ET). One booked into MindBody; one was refused. This page shows the evidence from all three systems.

Verdict: the approval flow worked correctly. The Friday class had been cancelled in MindBody overnight — after the request was created — so MindBody refused the enrollment, and the system marked the request Failed in HubSpot with the exact reason. The only defect was a too-vague error page for staff, fixed the same morning.

Fixes shipped (same morning)

FixBeforeAfter
Staff error page “MindBody booking failed. Staff: check admin queue.” Shows MindBody’s actual reason (e.g. “Class is cancelled and cannot be booked.”) and points staff to the Reassign link.
Booking calendar Cancelled classes could still appear as bookable (MindBody keeps them “available”), so a parent could request one. Cancelled classes are filtered out server-side. Verified live: the cancelled weekend classes no longer appear; only genuinely active classes show.

Net effect: this scenario can no longer start from the booking site, and if a class is ever cancelled after a request is made, staff now see exactly why the confirm was refused and what to do next.
